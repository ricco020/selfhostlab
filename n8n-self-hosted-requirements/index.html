Most guides repeat a minimum (often "1 vCPU, 2 GB RAM") without showing where it comes from. We installed n8n on a VPS, started it, sent it real executions and read the memory of every n8n process. Here are the numbers, how we got them and what server size they point to.

What we measured

The test server is a Contabo Cloud VPS with 8 AMD EPYC vCPU and 23 GB of RAM, so memory was never constrained: the figures below are what n8n asks for, not what it squeezes into. We installed n8n with npm install n8n (no Docker), kept the default SQLite database and the default task runner (the separate process that executes Code nodes), and summed the resident memory (RSS) of the main process and the runner with ps, sampled every 0.3 s.

CPU: is one vCPU enough?

For webhook-style workflows, n8n is not CPU bound. Even the test with a 5-million-step loop in a Code node kept p95 latency under 400 ms with 10 runs in parallel. Our server had 8 vCPU, so a 1 vCPU plan will be slower under parallel load: we have not measured it yet and will not guess a figure. If you expect bursts of parallel executions or heavy Code nodes, 2 vCPU is the safer choice.

Disk space

The npm install pulled 2,266 packages and took 2.9 GB on disk (3 min 20 s with a warm npm cache, 5 min 43 s without). After about 1,310 executions the SQLite database was 7.6 MB plus a 4 MB write-ahead log, so about 9 KB per execution of this small workflow. Workflows that move files or large JSON store much more per run. Self-hosted n8n prunes old executions by default, so 20 GB of disk is enough for a single-user setup that does not keep binary data.

How to reproduce this test

npm install n8n@2.35.7
N8N_PORT=5799 npx n8n import:workflow --input=wf.json   (download wf.json)
N8N_PORT=5799 npx n8n start
# then, in another shell, sample memory every 0.3 s:
ps -eo rss,args | grep -E 'n8n start|disallow-code-generation'

The workflow is a Webhook node (POST, respond with the last node) followed by a Code node that sums the integers up to n. Load was sent from the same server with 1 or 10 Python threads, so network latency is not included.

Limits of this test

  • npm install, not Docker. The official Docker image adds the container overhead (not measured here).
  • SQLite, not PostgreSQL, and no queue mode.
  • One workflow. Many active workflows with triggers and polling nodes will raise idle memory.
  • 8 vCPU host: throughput on smaller plans will be lower.

FAQ

Can n8n run on a 1 GB VPS?
Not reliably. n8n alone used 555 to 850 MB at idle and 780 MB at peak in our test, before the operating system and anything else. 2 GB is the practical floor.
How much RAM does n8n need?
Plan 2 GB for light personal use with SQLite, 4 GB if you add PostgreSQL and a reverse proxy, 8 GB for queue mode or several apps on the same server.
Is n8n CPU intensive?
Not for simple workflows: 13.5 executions per second one at a time, 26.5 per second with 10 in parallel, no errors. Heavy Code nodes and parallel bursts are what use CPU.
How much disk space does self-hosted n8n need?
2.9 GB for the install, plus about 9 KB per small execution in SQLite. 20 GB is enough for most single-user setups.
