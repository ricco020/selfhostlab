Ollama on a VPS without GPU, measured

Ollama 0.40.17 · CPU only · 3 models x 2 CPU sizes x 3 runs · tested 22 Nov 2026

Short answer. On 4 vCPU and no GPU, Ollama wrote 28 tokens/s with Llama 3.2 1B, 21 tokens/s with Llama 3.2 3B and 9 tokens/s with Llama 3.1 8B. The 8B model needed 5.4 GB of RAM: buy 8 GB for 8B, 4 GB is enough for 3B. Doubling the vCPU helped far less than the RAM size.

Articles about Ollama on a VPS give ranges like "5 to 15 tokens per second" without saying on what machine. We downloaded the official Ollama binary, pinned it to 4 and then 8 CPU cores, ran the same prompt three times per model and read the speed Ollama reports and the memory of its processes. Every number below comes from that run.

What 4 more vCPU buy you

Doubling the cores raised the 1B model by 42 % and the 8B model by 13 %, and gave nothing on the 3B model. On a CPU, each generated token means reading the whole model from RAM, so memory bandwidth caps the speed long before the core count does. For a VPS budget, that means: pay for the RAM the model needs first, extra vCPU second.

Limits of this test

  • The test server (Contabo Cloud VPS, 8 AMD EPYC vCPU, 23.5 GB RAM) also runs other services. Its 1-minute load average was 4.8 to 6.5 during the 4-core runs and climbed to 16.9 during the 8-core runs, which partly explains why 8 cores helped so little. Ollama ran at top CPU priority (nice -19) to reduce that effect. A quiet server of the same size should do as well or better.
  • One prompt (a 150-word technical answer, 45 to 60 prompt tokens, 200 tokens max, temperature 0). Long prompts and long contexts are slower and use more RAM.
  • Smaller VPS plans have fewer and sometimes slower cores than our test: treat the speeds as a ceiling for a 1 or 2 vCPU plan.
  • CPU only, no GPU. Ollama 0.40.17 official Linux binary, installed without Docker, models removed after the test.

Reproduce it

curl -sL -o ollama.tar.zst https://ollama.com/download/ollama-linux-amd64.tar.zst
mkdir dist && tar --zstd -xf ollama.tar.zst -C dist
OLLAMA_HOST=127.0.0.1:11499 taskset -c 0-3 dist/bin/ollama serve &
OLLAMA_HOST=127.0.0.1:11499 dist/bin/ollama pull llama3.1:8b
curl -s 127.0.0.1:11499/api/generate -d '{"model":"llama3.1:8b","prompt":"...","stream":false,
  "options":{"num_predict":200,"temperature":0,"seed":42,"num_thread":4}}' | jq '.eval_count/.eval_duration*1e9'

Going further: if you plan to run n8n next to Ollama, add its 555 to 850 MB to the RAM above.
